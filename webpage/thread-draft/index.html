Manipulation behaviors vary widely, but share a small set of reusable skills: wiping a table or a window is one skill. Planning with skills is how embodied agents generalize.

But agents can only plan with skills they know. Can VLMs discover them by watching?

Recovering skills from experience is the inverse of planning: it grows an agent's repertoire over time and turns raw video into skill-annotated data for training future agents.

Jianshu Zhang @your_handle2/7 · The task450 chars · folds

The task: a model watches videos one after another. Each time something is manipulated, it has to find when it happens, write it down as a skill like grasp(object, from), and decide: is this a skill it already has, or a new one?

Its skill library carries over from video to… video, so early choices shape later ones.

Our benchmark covers robot tabletop (DROID/RH20T) and kitchen (HD-EPIC) video: 12,429 verified skill calls over 48 kinds of actions.

Jianshu Zhang @your_handle3/7 · How we measure it428 chars · folds

How we score it, with three questions:
1) Did it find each action in time?
2) Did it group the same action together, and keep different ones apart? Names don't matter, only the grouping.
3) Did it create a skill the first time an action shows up, and reuse it after that?

In the… paper these are coverage (1); pair precision, pair recall, and ARI, where 0 = random (2); and create / reuse recall (3).

Jianshu Zhang @your_handle4/7 · Finding 1401 chars · folds

Finding 1: today's VLMs can't do this out of the box. We tested 19 open models. Their grouping is barely better than random, and bigger models don't reliably help.

They fail in two opposite ways. Models that watch the video and manage the library together (joint models) lump… different actions into one skill. Models that first describe the video in text keep inventing new names for the same action.

Alt text

Animated comparison: a joint model files pour under place, lumping different actions together; a text-based model creates grasp, pick_up and grab for the same action. 19 open VLMs; best grouping score at most 27 of 100; bigger models do not reliably help.

Jianshu Zhang @your_handle5/7 · Finding 2614 chars · folds

Finding 2: so we tried teaching them, three ways. All three clearly help: they beat no training in all 8 settings we tested. The difference is what library the model practices with:

A) Oracle history: the correct library. Biggest boost for joint models (grouping score 19 → 60… on robot video).
B) CLaRe (ours): same video, edited library. Remove the skill it needs and it must create one; add a look-alike and its answer shouldn't change. Helps in some settings, not all.
C) On-policy: it practices on the library it built itself, mistakes included, and gets corrected. Most reliable reuse for text-based models.

Alt text

Animated explainer of three fine-tuning methods: A trains with the correct library; B (CLaRe) edits the library, so the answer must change when a needed skill is removed and stay the same when a look-alike is added; C trains on the model's own library, mistakes included. Grouping score: 19.4 without training vs 60.0, 56.2, 56.3; all three beat no training in 8 of 8 settings.

Jianshu Zhang @your_handle6/7 · Finding 3445 chars · folds

Finding 3: but all three hit the same wall. They learn to reuse skills, not to create them.

After training, when an action repeats, joint models reuse its skill 97–99% of the time. When an action is new, they create one only 19–40% of the time.

On kitchen video the library… stops at 21–22 skills while 46 kinds of actions show up. Actions never seen in training (grating, shredding) are found in the video but almost never get their own skill.

Alt text

Animated chart from real data: over 40 kitchen videos, the action types seen rise to 46 while the learned library stops at 21 skills. After training, joint models reuse correctly 97-99% of the time but create a new skill only 19-40% of the time; unseen actions like grating are found but rarely named.
